# Trove · 抖音收藏整理与问答

在本机网页中扫描“收藏－视频”里的视频与图文，使用 OpenAI 兼容模型生成分类和收藏夹名称，预览后执行整理。

也可以在“收藏问答”中提问：本机转写视频语音、识别图文文字、建立中文检索索引，再由你配置的模型根据相关片段回答。支持连续追问、历史对话、作品来源、转写原文和时间位置；没有足够依据时明确提示。分类与问答沿用同一套模型服务配置。

## 启动

需要 Python 3.12+、uv，以及本机 Microsoft Edge（Windows 默认使用）。

```powershell
uv sync --frozen
uv run --frozen douyin-rag
```

打开 <http://127.0.0.1:8765>。更换端口：`uv run --frozen douyin-rag --port 8767`。仅监听本机，不需要注册网站或发布到云端。

在网页点击“查看示例”可以体验分类、筛选、改名和批量调整。示例模式不会向抖音发起写入。点击“使用我的收藏”后再连接真实账号。

## 使用步骤

1. **连接与设置**：填写 OpenAI 兼容服务地址、模型名、API 密钥。地址可为服务的 `/v1` 基础地址或完整 `/chat/completions` 地址。本机免密服务可不填密钥。
2. **连接抖音**：点击“扫码登录”，当前设置页会展示真实抖音登录页中的二维码，本机浏览器在后台运行，不弹出额外窗口。用抖音 App 扫码并在手机上确认后，应用检测到会话 Cookie 就自动保存登录状态并关闭后台登录浏览器，可以直接使用收藏功能，不再额外请求收藏接口来验证登录。二维码过期可以刷新。也可填写已有 douyin-mcp 的外部登录状态文件路径；此时以显式配置为准，扫码后如想改用本应用会话，请清空外部路径再保存。
3. **扫描收藏**：遍历全部收藏、收藏夹和夹内作品，按作品 ID 去重并记录原归属。中途失败不会覆盖上次完整快照。
4. **生成分类方案**：模型先根据均匀采样的全量标题设计分类，再逐批给每条作品归类。当前依据标题、描述与作者信息，不下载视频、转写语音或 OCR。内容不足会进入“待复核”或标记低置信度，不声称已经观看内容。
5. **预览**：查看分类依据；修改每条作品的目标分类或收藏夹名称；支持多选批量调整。尚未返回有效结果的作品显示“待分类”。不完整的模型批次不会写入方案。
6. **确认并整理**：先安装并打开 Ego Lite，确认 `ego-browser` 命令可用，并在 Ego Lite 登录与扫描时一致的抖音账号。确认方案后，应用会在 Ego Lite 打开 Trove 整理页面，查询或通过网页接口创建私密目标夹，再按目标夹分批移入。首批最多 3 条，确认多条作品都已进目标夹后，每批最多 10 条。移入批次串行执行，间隔取操作间隔与 5 秒中的较大值。暂停后可以继续，续跑会按夹读取当前成员，跳过已经移入的作品。
7. **核对结果**：移入请求处理完后按目标收藏夹统一核对，分页按游标顺序读取。只有确认作品已进目标夹，才会清理并核对旧归属。原收藏夹和作品的收藏状态会保留。重新扫描或分类会将旧快照和方案归档，可在“整理记录”导出。

“全量”指平台实际返回的全部可读作品。隐藏、删除等不可读条目的原始分页提示单独保存；不把可读数量当成账号总收藏数，也不盲目累加可能在多页重复的无效条目数。

## 收藏问答

1. 完成抖音登录并扫描收藏，然后打开“收藏问答”。分类与移动收藏夹不是问答的前置条件。
2. 点击“处理作品内容”。视频会即时读取详情和媒体地址，临时下载视频，在本机用 `faster-whisper` 的 CPU INT8 模式转写，保留时间戳；图文会即时读取图片地址，在本机用 RapidOCR 识别图片文字，并与原文案一起保留。处理完当前作品后临时媒体自动删除。
3. 视频按原有语音片段分段，图文按原文案和图片文字分段，由 `BAAI/bge-small-zh-v1.5` 本机向量模型建立索引。检索结合语义相似度与中文关键词；标题和作者只作为来源信息，不充当正文。
4. 处理进度按作品保存。暂停在当前作品处理结束后生效；再次点击处理或继续任务会跳过已完成作品，重试失败作品。新增收藏扫描后只处理尚未建库的作品。切换语音转写模型后会重新处理视频，图文使用本机识别，不受语音模型影响；旧快照和当前收藏之外的作品不会进入本次检索。
5. 在连接与设置中填写模型服务地址、名称和 API 密钥后提问。问答向该服务发送当前问题、近期问题和相关文字片段，不发送视频音频或图文图片。回答会列出来源和时间位置，点击“打开原作品”可回到作品页面；时间位置显示在本应用内，不保证抖音网页支持跳到该秒数。
6. 追问沿用当前对话；用“新对话”开启其他主题，或从对话下拉框恢复历史。历史保存在本机并按扫描账号隔离，不依赖浏览器临时存储。

默认 `small` 模型下载约 486 MB；`base` 约 148 MB，可在设置中切换。本机中文向量模型另需约 90 MB；图文识别模型随依赖安装，不需要单独下载。这些是模型文件大小，不包含 Python 依赖与缓存占用。首次使用需要联网下载公开模型，不需要注册转写账号，也不需要安装系统 FFmpeg 或 CUDA；后续使用缓存。网络不可达时会保留进度并报错，可以在网络恢复后重试。

手动问答的视频处理使用可识别语音，不提取视频画面字幕、不做视频画面 OCR 或无声演示理解；图文作品使用本机 OCR 识别图片文字和原文案，单条图文最多处理 100 张图片，文字总量超过 50000 字时会明确失败而不截断。单条视频上限为 60 分钟、256 MiB。语音识别和图文识别可能受口音、背景音乐、字体和排版影响，重要内容应核对原作品。媒体接口非官方，删除、私密、登录失效、媒体地址域名变化或风控都可能导致失败。界面分别统计已可问答、待处理、失败的作品，不将“任务结束”当作“所有作品成功”。

“体验合成示例”使用独立的合成转写，演示关键词检索、追问、来源与历史，不下载媒体、不加载本机模型、不调用云端服务；示例作品不提供伪造的真实链接。

## 每日新增收藏汇总与自动整理

在 Windows 上注册每天北京时间 **06:00** 的任务，关闭网页、退出 Trove 后仍由系统启动：

```powershell
uv run --frozen douyin-rag --daily-schedule install
uv run --frozen douyin-rag --daily-schedule status
```

先完成 Trove 的抖音登录，Ego Lite 也需登录同一账号并保持可用。日报还需要安装 Codex CLI，并通过 `codex login` 使用当前 ChatGPT 订阅登录，`codex login status` 可核对登录方式。任务以当前 Windows 用户的普通权限运行，不保存 Windows 密码或将 Cookie、模型密钥放入任务参数。需要电脑开机且该用户已登录；系统会尝试唤醒睡眠中的电脑，实际能否唤醒取决于设备与电源策略。关机或用户未登录时无法准点运行，恢复条件后由系统补跑。六点是开始时间，完成时间取决于新增作品数量、本机转写速度、订阅额度和网络。

**首次运行只建立当前收藏基线，不处理历史收藏。** 可以在注册后手动执行一次以下命令建立基线；否则由首次六点任务建立。之后处理的是“上次成功自动扫描后新增的作品”，不是昨天 00:00—24:00；手动工作台扫描不消耗这份增量。切换账号时分别建立基线并隔离待办。

```powershell
uv run --frozen douyin-rag --daily-run
```

- 日报按主题分组，每条显示可点击原作品的具体标题（40 字以内）和内容简介（不超过 100 个字符，含标点和空格），不列重点清单。标题交代作品、产品或具体主题；影视片段优先保留有文字依据的剧名，无法确认时写明“影视片段／剧名未确认”，不把剧情台词泛化成管理或战术知识。
- 视频分析、图文分析、画面识字、日报总结及自动分类通过官方 `codex exec` 复用已登录的 ChatGPT 订阅，固定请求 `gpt-6-luna`、`model_reasoning_effort="xhigh"`。这会消耗订阅的 Codex 额度；登录、额度或模型不可用时明确失败并保留进度，不切换到其他模型。原有手动分类与收藏问答继续使用网页中配置的兼容服务。CLI 以只读、无会话持久化的方式在临时目录运行，禁用命令执行、浏览器、插件、搜索等工作能力；由 CLI 自行管理订阅登录，不读取、导出或复制登录令牌，也不使用 API 密钥计费。
- 沿用本地转写与知识库缓存，最多抽取 8 张带时间位置、长边不超过 1024 像素的画面，结合原标题读取字幕、片名和产品标识。无语音时先尝试画面识字；画面也不可用时可根据原标题推断，简介必须标注“仅据标题”。图文作品先用本机 OCR 识别全部图片文字，再取最多 8 张图片预览参与视觉分析；OCR 文字仍覆盖全部图片。不能确认的名称和内容不编造。长视频保留分段汇总，最后才生成百字简介；超长输出校验后重试，不直接截断。
- 抽帧图片、图文图片及转写/识别文字会通过订阅发送给 OpenAI。临时视频、图片与 CLI 输出处理后清理，日报 JSON 仅缓存文字分析、证据来源和分析版本；OCR、抽帧和语音识别均可能遗漏或误识别，少量抽帧不等于观看全部画面。视频画面文字不会写成语音原文；图文作品的图片文字会作为图文正文单独索引。
- 自动分类优先沿用上次自动分类、手动方案中的分类，其次使用已有收藏夹名称；没有可用分类时才生成新分类。只移动新增作品，新建缺少的私密收藏夹；目标成员确认后清理这些作品的旧归属，保留原收藏夹和收藏状态。
- 日报与移动分别保存进度。转写、识别或摘要失败仍可完成分类移动，移动失败仍保留日报；后续运行重试未完成步骤，同时接收新一批新增作品。同日不重复创建日报，写入响应不明确时先读取目标夹核对，已经取消收藏的待办不会被自动移回。
- 后台任务与手动长任务互斥，任务计划也禁止自身重叠运行。登录失效、验证码、账号不一致或接口拒绝时停止相应步骤并保留进度；处理好 Ego Lite 的整理页面后，可再次运行 `--daily-run` 继续。后台失败会由任务计划每隔 30 分钟重试，最多 3 次；仍失败的待办留到后续运行。

日报保存在运行目录的 `daily/YYYY-MM-DD-批次ID/report.md`，同目录的 `report.json`、`workspace.json` 保存摘要与移动进度。全局增量基线保存在 `daily-state.json`，最近一次结果保存在 `daily-last-run.json`。这些是本机个人数据，不进入 Git；自动任务不会覆盖手动工作台的快照、分类方案或整理历史。暂无网页日报入口，直接打开 Markdown 文件查看。

旧版已生成的日报保留原文件。另存修订版时重新采集原作品画面或图文图片并复用已有文字，生成新分析，不以旧的泛化摘要作为新依据；可另存 `report-reviewed.md`，不扫描全量收藏、不移动收藏，也不修改原日报 JSON 和处理记录。仍待重试的旧批次在后续正常执行时，会按分析版本补采画面并更新为新格式。报告保留“仅据标题”等不确定性说明。

停止自动执行（保留本机日报和进度）：

```powershell
uv run --frozen douyin-rag --daily-schedule remove
```

需要指定运行目录时，在上述命令后加 `--state-dir "绝对路径"`；同一目录对应同一个任务，重复安装只更新本应用的任务，遇到同名但不属于本应用的任务会拒绝覆盖。任务固定使用安装时的 Python 和项目工作目录，移动项目或重建虚拟环境后需重新安装任务。临时终端环境变量不会被复制到任务配置，后台模型与登录配置应使用本机设置或 Windows 用户环境变量。

## 本机配置与数据

默认运行目录是 Windows 的 `%LOCALAPPDATA%/douyin-rag`，其他系统为 `~/.local/share/douyin-rag`。可通过 `DOUYIN_RAG_STATE_DIR` 自定义。

- 模型设置、密钥、扫描快照、方案和进度写入运行目录，不进入 Git。模型密钥存于本机设置文件，未加密；若不希望落盘，可以使用环境变量。接口和导出的记录均不返回密钥。
- 登录沿用 `DOUYIN_COOKIE`、`DOUYIN_COOKIE_PATH`，或 `XDG_CONFIG_HOME/douyinmcp/cookies.txt`（未配置 XDG 时为 `~/.config/douyinmcp/cookies.txt`）；也支持本应用扫码后的独立浏览器会话。
- `DOUYIN_RAG_API_BASE`、`DOUYIN_RAG_MODEL`、`DOUYIN_RAG_API_KEY` 可提供或覆盖模型配置。不要把真实值放进仓库或粘贴到聊天中。
- `DOUYIN_RAG_BROWSER` 可指定已安装 Chromium 系浏览器的可执行文件；未使用本机 Edge 的环境可运行 `uv run playwright install chromium`。
- 浏览器配置、登录状态文件、模型请求正文不会出现在导出和应用访问日志中。收藏快照本身包含个人收藏信息，按需自行保管。
- `knowledge.sqlite3` 保存转写、片段、向量与聊天记录，`models/` 保存模型缓存，都位于上述运行目录，按扫描账号隔离。现有“导出记录”仍只导出收藏整理记录，不包含知识库和聊天记录。本机数据库及历史记录未加密，请按个人数据保管。
- 本地转写不会上传音频，但云端问答会收到问题和相关转写片段。首次启用问答前，应选用你愿意向其发送这些文字的模型服务。模型内的提示注入防护与引用编号校验不能保证每个自然语言结论完全正确，重要结论应核对展示的原文。

## 写入范围与验证限制

读取复用 douyin-mcp 的 HTTP 客户端协议、本地签名和响应校验，扫码与外部 Cookie 均走同一条收藏读取链路。扫码浏览器的 User-Agent 与读取客户端保持一致，登录后提取抖音域及其子域的 Cookie。二维码仅从登录页指定元素截取，在本机页面展示，不写入项目、导出或日志。Ego Lite 在已登录抖音页面内发送建夹和移动请求，再由本机扫描会话读取并核对结果。Ego Lite 的登录凭据留在该浏览器内，每次写入前会校验会话指纹。

这是非官方网页接口。接口协议变化、验证码、会话失效或风控都可能中止操作。如果 Ego Lite 提示登录或验证，在该整理页面处理后点击「继续整理」。若无法确认 Ego Lite 的会话与扫描快照一致，应用会停止写入。接口拒绝、超时和核对失败时会保留进度，续跑会先查询抖音。自动化测试使用模拟抖音与模型服务。

```powershell
uv run --frozen python -m unittest discover -s tests -v

```

测试覆盖收藏分页/去重、图文、图文图片下载与本地 OCR、超长 ID、签名运行时、无效作品提示、模型异常与断点续分、方案修订、账号变化、移动写后核对、进度恢复、归档、密钥脱敏及本机请求边界。不使用真实生产凭据或真实收藏进行测试。

问答测试还覆盖媒体地址和重定向限制、下载大小上限、带时间戳转写、图文 OCR 与来源 URL、分段、增量处理与重试、账号隔离、移出收藏后的检索过滤、追问、历史恢复、引用编号校验、无依据拒答和示例模式不调用模型。依赖中的 `av==16.1.0` 固定为已验证兼容版本，避免新版移除解码参数造成转写失败。

## 代码范围

- `collections.py`：按函数提取的收藏读取与作品整理。
- `signing.py`、`verification.py`、`assets/abogus.js`：读取所需的签名与校验；签名脚本移除了无关前置补丁和演示查询。
- `organizer.py`：扫描、OpenAI 兼容分类、方案编辑、状态与归档。
- `writer.py`：本机浏览器扫码登录。
- `ego_writer.py`：Ego Lite 会话接入、建夹、移动与核对。
- `app.py`、`web/`：本机 API、网页及静态资源。
- `content.py`：媒体地址校验、受限临时下载、本机语音转写和图文图片文字识别。
- `rag.py`：本机 SQLite 知识库、向量与关键词检索、会话和引用校验。
- `daily.py`：独立增量基线、作品日报、自动分类移动与分步恢复。
- `scheduler.py`：Windows 每日六点任务的注册、查询和移除。

没有复制原 MCP 服务端、搜索、评论、推荐流、媒体下载、ASR 或 OCR 的实现、运行目录或整个原项目；本项目的内容下载、语音转写和图文识别集成为独立实现。
